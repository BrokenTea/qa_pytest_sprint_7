⚙️ Установка и настройка
Клонируйте репозиторий:

bash
git clone <repository-url>
cd qa_pytest_sprint_7
Установите зависимости:

bash
pip install -r requirements.txt
Убедитесь, что у вас установлен Allure Commandline для генерации отчетов.

🚀 Запуск тестов
Запуск всех тестов
bash
pytest
Запуск тестов с генерацией Allure отчетов
bash
pytest --alluredir=allure-results
Просмотр отчета Allure
bash
allure serve allure-results
Запуск конкретных тестов
bash
# Только тесты создания курьера
pytest tests/test_courier_creation.py

# Тесты с определенным маркером
pytest -m "login"
🎯 Особенности реализации
1. Использование Faker для генерации тестовых данных
Проект использует библиотеку Faker для генерации реалистичных тестовых данных:

Логины, пароли, имена курьеров

Адреса, телефоны, комментарии для заказов

Данные для негативных тестов (пустые строки, специальные символы и т.д.)

Все данные генерируются детерминированно (с установленным seed) для воспроизводимости тестов.

2. Паттерн Page Object Model (POM)
Проект следует паттерну POM, разделяя:

API клиенты (api_clients/) - инкапсулируют логику работы с API

Тестовые данные (data/) - содержат методы генерации данных

Моки (api_mocks/) - имитируют ответы API для изолированного тестирования

Тестовые сценарии (tests/) - содержат непосредственно тесты

3. Mock-объекты
Для изолированного тестирования API используются моки, которые позволяют:

Тестировать бизнес-логику без реальных вызовов API

Имитировать различные ответы сервера (успешные, ошибки)

Контролировать данные, возвращаемые API

4. Allure отчеты
Проект настроен для генерации детализированных отчетов Allure с:

Разделением тестов по функциональностям (features) и сценариям (stories)

Динамическими заголовками и описаниями тестов

Тегами для маркировки тестов

📊 Генерация тестовых данных
Класс CourierData в test_data.py предоставляет методы для получения тестовых данных:

python
# Валидные данные курьера
courier_data = CourierData.get_valid_courier_data()

# Данные для логина
login_data = CourierData.get_login_credentials()

# Данные заказа с цветом
order_data_black = CourierData.get_order_data_with_black_color()

# Негативные данные
empty_login_data = CourierData.get_courier_data_missing_login()
Статические данные для тестирования
Проект включает предопределенные данные для:

Негативных тестов (пустые строки, специальные символы)

Предопределенные логины и пароли

Цвета самокатов и станции метро

Тестовых пользователей для разных сценариев

Преимущества использования Faker:
Реалистичные данные - имена, адреса, телефоны выглядят как настоящие

Детерминированность - благодаря seed данные генерируются одинаково при каждом запуске

Гибкость - легко генерировать данные для разных сценариев

Читаемость - код тестов становится более понятным

🔧 Технические детали
Поддерживаемые параметры запросов:
courierId - фильтрация заказов по ID курьера

metroStation - фильтрация по станциям метро (может быть массивом)

limit - количество заказов на странице (по умолчанию 30)

page - номер страницы (по умолчанию 0)

Цвета самоката:
["BLACK"] - черный самокат

["GREY"] - серый самокат

["BLACK", "GREY"] - оба цвета

[] - без указания цвета
